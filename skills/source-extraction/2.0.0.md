Project ManagAIr Source Intelligence extraction v2.

OUTPUT
Return exactly one JSON object and nothing else — no prose, no markdown fence:
{"rows":[{"registerName":"Actions","row":{"client_ref":"Actions-412","op":"add","proposed_id":"$ALLOC","target_id":null,"title":"...","summary":"...","status":null,"record_type":null,"owner":null,"due_date_raw":null,"source_ref":"<sourceId>","related_refs":[],"supersedes":[],"anchors":[{"segment_seq":412,"speaker":null,"t_ms":null,"quote":"..."}],"derivation":"fact","reasoning":null,"confidence":"high","discharges_markers":[],"details":{}}}],"windowCoverage":[{"key":"1","status":"reviewed","itemCount":3,"explanation":null}],"categoryCoverage":[{"key":"Actions","status":"populated","itemCount":3,"explanation":null}],"markerDismissals":[]}
Every element of "rows" is exactly {"registerName": <register>, "row": {<the fields above>}} — the register name sits BESIDE the row object, never inside it.
Unknown keys are rejected. Every row is a proposal about this source only; never restate register state.

REGISTERS — each row belongs to exactly one:
Decisions       a choice that has been made and closes an option.
Actions         work someone has committed to do.
Risks_Issues    a threat to delivery (risk) or a live problem (issue).
Config_Changes  a change made to, or asked of, the system's configuration, settings or records.
Open_Questions  an unanswered question someone must answer.
Milestones      a dated or conditional delivery point.
Entities        a person, team, organisation or system named in the source.
Sources         one row describing this source artefact itself; its title is the original file name.
Uncertainty     anything you could not resolve: ambiguous owner, unclear date, conflicting statements, low-confidence reading.

OPERATIONS
op "add": proposed_id MUST be "$ALLOC" and target_id MUST be null. Never invent a durable id.
Every other op: proposed_id MUST be null (or exactly target_id). Identifiers are allocated server-side.
op "update", "resolve", "supersede", "reaffirm": target_id MUST be an externalId taken from existingRows.
client_ref is unique across the whole packet. Derive it deterministically as <register>-<lowest anchored
segment_seq>, e.g. "Actions-412". Windows overlap, so the same statement can reach you twice: emit it once, on its
earliest segment, with byte-identical field values each time you see it.
related_refs and supersedes hold existing externalIds only; default [].
derivation "fact" or "inference"; "inference" REQUIRES a non-empty reasoning string.
confidence is high, medium, low or unknown — your own reading, not the marker's.

FIELD SEMANTICS (update family)
null means "this source did not speak to this field": the stored value is left untouched.
"" (empty string) explicitly clears the field.
So never echo an unknown field as null-with-intent, and never guess owner, status or a date to fill a slot.
due_date_raw carries the source's own wording ("end of next week"), never a resolved date. status uses the
source's wording, normalised conservatively, or null when the source states none (an added row then defaults to open). record_type is the source's own noun for the item, or null.

ROW KEYS — a row object contains EXACTLY these keys and no others. Any extra key rejects that row:
client_ref, op, target_id, proposed_id, title, summary, status, record_type, owner, due_date_raw, source_ref,
related_refs, supersedes, anchors, derivation, reasoning, confidence, discharges_markers, details.
There is no "topic", "category", "notes", "id" or "date" key. Anything else you want to say goes in summary or in
an allow-listed details key.

ANCHORS — every row needs at least one {segment_seq, speaker, t_ms, quote}
segment_seq MUST be a seq present in the supplied windows.
speaker, when supplied, MUST equal that segment's speaker exactly (only case and whitespace are folded).
A wrong speaker is a blocker, so supply null unless the payload shows you the speaker on that exact segment.
t_ms, when supplied, MUST be within 30000 ms of that segment's tStartMs. Supply null if unsure.

QUOTES
derivation "fact": every anchor MUST carry a verbatim quote.
derivation "inference": quote MAY be null, but any quote you do supply is verified just as strictly — omit it
rather than approximate it.
A quote MUST appear contiguously inside its anchored segment or an immediately adjacent segment (seq +/- 1).
Never stitch words from two segments into one quote, never elide with "...", never tidy grammar or punctuation.
Curly quotes, dashes and case are folded for you; nothing else is.
A quote MUST be at least 4 words and 20 characters, unless it is substantially the whole of a short segment.
If a segment is too terse to yield a valid quote, anchor on the neighbouring segment that carries the words.

CLAIM SUPPORT
A row's title and summary MUST share at least one substantive word (over 2 characters, not a stopword) with the
segments it cites. Paraphrase freely but keep the source's own nouns. Sources rows are exempt.
An Entities row's title MUST appear in the segments it cites or in the source's participant list.

MARKERS
Each window carries "markers": pre-detected governance cues, {id, seq, confidence}. The id ends in the cue type
(explicit-action, explicit-register, explicit-date, scheduled-time, live-config-act, commitment-pattern,
question-pattern, constraint-pattern); read the segment at seq for what was actually said.
For EVERY marker with confidence "high" do exactly one of:
 (a) emit a row whose discharges_markers contains that id verbatim AND which is anchored within 3 segments of the
     marker's seq; or
 (b) list it in markerDismissals as {"markerId":<id>,"reason":<specific reason it carries no governance content>}.
Prefer (a). A dismissal is only a proposal to an operator, so on this pass it does not satisfy the gate; dismiss only
genuine false positives, and discharge anything carrying governance content however small.
Silence on a high marker fails the packet. Never claim an id you were not given, and never discharge a marker from a
row anchored elsewhere. "medium" markers are recall hints only; no discharge is required.

COVERAGE
windowCoverage: exactly one entry per requested window, key = the window seq as a string.
categoryCoverage: exactly one entry per requested category, key = the register name.
status is one of reviewed, populated, none-found, uncertain, no-governance-content. Never "failed": if a window was
hard to read, say so in explanation, do not fail it.
itemCount is the number of rows you anchored INSIDE that window's startSeq..endSeq range. It may never exceed that
number, so count anchors rather than estimating.
Any entry with itemCount 0 needs a non-empty explanation, and any category with status "none-found" needs one.

MANDATORY ROWS
Emit exactly one Sources row, always. It is exempt from the vocabulary check but not from the anchor and quote rules:
anchor it on an opening segment and quote that segment verbatim.
If the source has more than one participant, emit Entities rows or explain their absence in the Entities category
explanation.
If you emit no Uncertainty rows, explain that in the Uncertainty category explanation.

DETAILS
"details" accepts ONLY these keys; any other key rejects the packet:
rationale, options_summary, outcome, decision_needed_by, driver, evidence, impact, mitigation, likelihood, severity,
environment, change_type, follow_through, question, parked_with, unblocked_by, blocking, target_date,
milestone_status, conditional_logic, entity_type, aliases, alias_confidence, disambiguation_note, hypothetical,
source_type, why_uncertain, resolve_by, resolution_route.
Values are scalars or arrays of scalars. Omit a key rather than filling it with a guess.

NEVER INVENT
provider identity, durable register ids, source text, dates, owners or status. If the source does not say it, it
belongs in Uncertainty or nowhere.
